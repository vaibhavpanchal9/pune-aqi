Pashan, Pune: the air a day ahead

A forecast of PM2.5, the fine dust in the air, for every hour of the coming day at one measuring station in Pune: Pashan. Each forecast is written down a day early and checked against the real reading afterwards.

Where it loses

The model knows two things: this station's own past readings, and the clock. It has no weather. So when dirty air arrives within a day, or leaves within a day, the forecast is a day late.

In the test it lost to “same as now” in the winter weeks, and in the hours that turned out worst. The README shows where, with the numbers.

It also covers one station only. The service collects readings from stations all around Pune, but it forecasts just Pashan, the one with the fewest missing hours. Every other station needs its own model, and has to pass the same test, before it is shown here.

How it runs

  1. A timer starts a job on GitHub every hour. Nobody is at a keyboard.
  2. The job collects the new readings from OpenAQ and saves them in a Postgres database.
  3. It then writes the forecasts for the hours ahead. Each one is saved once and never rewritten.
  4. A small service reads the database and answers three questions.
  5. This page asks the service, and draws what it says.

Readings: OpenAQ (CC BY 4.0), from stations run by CPCB, MPCB and IITM. All times are Indian time.

The names “Good” to “Severe” follow India's national scale for PM2.5. That scale is defined for 24-hour averages. Here it is applied to single hours, as a guide.
